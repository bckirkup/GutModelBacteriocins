## 1. Executive verdict

**Devin understood the core mathematics. This was not symptom patching.** PR #359 restores the two required translated and reflected Neumann source families in shared host/device code, replaces a fixed image count with an adaptive shell budget, and adds independent wall, modal, mass, and physical-device checks. PR #360 correctly notices that a device counter that merely exists is not evidence, forces the cap path, asserts nonzero and exactly equal host/device counts, and fixes the test-name trigger. PR #361 adopts the central Robin design rather than disguising the old sealed wall: it implements `G_Robin = G_sealed + ΔG`, retains an independently callable modal oracle, keys correction tables by source transport parameters, carries the signed normal-flow gauge transform, exposes effective and free transfer bases, ships the feature disabled with `δ = inf`, and exercises it on an actual Amazon Web Services (AWS) T4.

The response nevertheless becomes incomplete at numerical edge contracts. The most serious newly reproduced defect is in the eigenvalue solver itself. For the actual shipped ColE1 transport tuple, branch zero can straddle a rational pole. The code then bisects a discontinuity and silently returns the pole as an eigenvalue, with no governing-equation residual check (`src/diffusion/robin_correction_table.cpp:60-107,224-247`). Enabled Robin therefore remains a **no-go** until this is fixed. This exact execution also corrects our live preliminary prediction: it does not throw for this tuple; it silently succeeds at the pole.

Two CUDA blockers remain. A launch with more than 64 live table identities can remap an evicted, still-live table to index 64 and read outside a 0 to 63 device table array (`src/gpu/greens_function_gpu.cpp:91-155`; `src/gpu/gpu_common.cuh:110-120`). CUDA also always interpolates where CPU invokes a 2,048-mode near-wall/axis fallback (`src/diffusion/greens_function.cpp:376-395`; `src/gpu/gpu_common.cuh:110-127`). Final provenance is not final: it is written before normal lazy table construction and then latched (`src/core/simulation.cpp:551-559,582-587`; `src/io/hdf5_writer.cpp:576-663`).

> **Decision:** accept PR #359 for the screened, zero-normal-flow sealed envelope and accept PR #360 for its narrow cap-provenance claim. Accept PR #361's architecture, but do not accept enabled Robin for production. The default `δ = inf` path remains safe from Robin-specific defects and uses the corrected sealed kernel (`src/diffusion/qssa_solver.h:41-46`; `src/diffusion/greens_function.cpp:361-367`).

## 4. What Devin got right

### 4.1 PR #359 repaired the governing source construction

The earlier implementation duplicated reflected images and omitted translated images. PR #359 replaces it with both required families, `z_s + 2nH` and `-z_s + 2nH`, in one shared header used by CPU and CUDA (`src/diffusion/neumann_image_series.h:63-75`; `src/diffusion/greens_function.cpp:346-351`; `src/gpu/gpu_common.cuh:103-109`). The adaptive shell budget, relative stopping rule, cap, and forced-cap accounting are real (`src/diffusion/neumann_image_series.h:17-52,78-107`). The added tests do not merely call the production function as their oracle. They check zero-normal-flow wall derivatives, an independent modal representation, global mass balance, and a representative physical setting (`tests/test_neumann_image_series.cpp:57-218`).

That is a scientifically appropriate correction. It also responds well to the repository's valid criticism that the old bounded/FMM comparisons were legitimate superposition tests, not boundary-condition tests. The correct response was to retain them and add independent boundary tests, which PR #359 did.

The acceptance envelope must remain explicit. Reversing `U_z` for reflected images means each reflected term solves a mirrored-drift PDE, not the same PDE as the translated terms. The repository now reports an interior residual of about 0.29 versus 0.0014 for a converged mode sum, while selected shipped settings show field differences of only 0.12% to 0.69% (`docs/ROBIN_LUMEN_BC.md:239-251`). This is a moderate measured error in those cases, but it prevents a claim of an exact Neumann solution under wall-normal flow. Low-screening ordinary runs also use an inaccurate eight-shell floor and warn; strict configuration rejects them. That is safer than the old silent fixed truncation, but warning is not accuracy.

### 4.2 PR #360 closed the specific device-evidence gap

PR #360 is the cleanest response of the three. It recognized that a cap counter could remain dead code while tests passed. The revised test deliberately reaches the cap, asserts that both host and device counts are nonzero and exactly equal, and checks the unscreened field (`tests/test_neumann_image_series_gpu.cpp:89-134`). The physical T4 run reported 5,780 equal hits. This is not a paper assertion inferred from compilation; it is execution evidence.

The only remaining qualification is trigger breadth. The dedicated workflow still watches a narrow set of file paths (`.github/workflows/gpu-device-tests.yml:3-11`). Changes in shared `src/diffusion/**`, `src/fields/**`, `src/core/**`, or build files can alter CUDA behavior without a filename containing `gpu`. That is a continuous-integration (CI) coverage issue, not a reason to reject PR #360's narrow fix.

### 4.3 PR #361 adopted the scientific design, including inconvenient consequences

Several choices show genuine understanding:

1. **Correct decomposition.** Production reconstructs the sealed image result plus a correction, while table construction independently subtracts sealed modes from Robin modes (`src/diffusion/greens_function.cpp:369-403`; `src/diffusion/robin_correction_table.cpp:300-308,401-423`).
2. **Source transport identity.** The quasi-steady-state approximation (QSSA) source retains `diff_coeff`, retardation, decay, transfer settings, and target filtering copies each full parameter object (`src/diffusion/qssa_solver.cpp:335-357,381-394`). This avoids one BtuB table for physically distinct ColE1 and ColE2 sources (`src/genome/plasmid.cpp:37-70`).
3. **Signed gauge transform.** The code uses `a = U_z/(2D)`, distinct lower and upper transformed coefficients, and runtime restoration of signed drift (`src/diffusion/robin_correction_table.cpp:224-247,348-379`; `src/diffusion/greens_function.cpp:397-399`). This follows the prior memo's instruction to re-derive wall signs.
4. **Choice of concentration basis.** Effective and free transfer bases are explicit, with `k_c = D_eff/δ` or `D_free/δ` (`src/diffusion/robin_correction_table.cpp:131-147`; `src/io/input_parser.cpp:830-843`).
5. **Independent oracle and bounded design.** The direct modal path remains callable; interpolation is shared; the cache is bounded to 64 least-recently-used entries; metadata and counters exist (`src/diffusion/robin_correction_table.h:69-181,198-210`). These are good architectural ingredients even though their edge contracts need repair.
6. **Conservative default and biological honesty.** `δ = inf` leaves the boundary disabled. Enabling `δ = 100 µm` causes four biological tests to fail because exposure changes, and the repository does not weaken those tests merely to make the feature pass (`docs/ROBIN_LUMEN_BC.md:178-197`). That is the right interpretation: the boundary is a scientific intervention, not a numerical refactor.
