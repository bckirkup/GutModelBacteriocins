| **Wall-normal drift in the sealed image series** | Fixed, opt-in correction | #391 | Reflected images reverse `U_z`, so the legacy series and previous in-tree sealed modal field enforce zero diffusive flux instead of physical zero total flux (wall-flux residual `+0.451` for both versus `2e-10` for the corrected sign). | **Dysbiosis guard noise sensitivity** | Fixed | #287 | The former per-sample strict-increase and non-deceleration criterion was effectively unfirable on stochastic trajectories: one density dip reset the seven-sample window. | **Dysbiosis halt artifact visibility** | Fixed | #289 | Run-level termination metadata is written under `/run_provenance/`, so guard-halted runs are distinguishable from full-horizon completions even when the final summary was written before the guard evaluation. |
| **Carbon VBF overdraw** | Fixed | #258 | The Monod carbon sink is implicitly integrated on both host and CUDA paths from one shared closed-form helper, and realized removal is reported; reaction clips are accounted. Agent-side uptake overdraw is closed by the `uptake_limit` model: `delivery` integrates the per-agent first-order sink with diffusion and funds growth only from realized removal; `sherwood` caps per-agent per-step uptake at the quasi-steady diffusive delivery `4*pi*D_eff*r*C_local`, funds the biomass increment and `mu_realized` at the same fraction, and reports demanded uptake plus bound-agent counts; `voxel` is a diagnostic-only grid-artifact probe and `none` (default) keeps the historical unfunded behaviour. The legacy zero-order agent sink could not brake density because it was clipped before diffusion in a single voxel, so nearly all requested carbon was never removed from the field. Under gradient-preserving transport, the diffusion solve subtracts the reference profile to solve the perturbation `P`, includes the `-sG` sink RHS, and restores `G` afterward; biology-time delivery reads the stored full field with `conc_global`, not `P+G` a second time. |
| **Ambient ROS mortality** | Fixed | #343 | ROS-driven SOS induction was priced as `k_ROS × [O₂]_ambient × mu_realized` — oxygen no cell acquired — and with the uncited `k_ROS = 1e2` it accounted for 99.5% of cumulative SOS hazard and for every population loss in the oxygen series (#332). The shipped `k_ROS` default is now `0.0`, retiring ambient ROS mortality by default. A funded driver prices induction from each agent's funded respiratory oxygen flux, in either a specific (kg/mol) or absolute (mol⁻¹, per-generation calibratable) normalization (#339), and the four SOS hazard components are emitted per step. The ambient path remains reachable by explicitly setting a positive `oxygen.k_ROS`; see `docs/DELIVERY_ROS_CAMPAIGN.md`. |
| **Delivery rationing accepted negative fields** | Fixed | #340 | Prescribed delivery mass was removed unconditionally and, after two retries, a negative solve was accepted, so the field borrowed against undelivered supply (min oxygen `-9.9e-6` at 500 agents) while remaining mass-exact — a positivity failure, not an accounting one (#338). Rationing now iterates to feasibility, local reductions first and a global bisection guarantee second, never accepts a negative solve, and reports a per-species rationing factor. |
| **CUDA delivery parity** | Fixed, narrow device scope | #343 | Route B solves delivery diffusion on device for replicated single-rank runs with line lengths up to 512, carrying both sink terms (agent uptake as prescribed RHS mass, the first-order VBF sink in the implicit diagonal) with per-cell realized removal read back to fund biomass; the positivity rationing policy stays single-sourced on the host, driven by device-backed negativity and reduction callbacks. Everything outside that scope — slab mode, `nprocs > 1`, longer lines, unsupported boundary combinations, incomplete device capabilities — falls back to Route A and records `host_forced_delivery` in `/run_provenance/chemistry_placement`; `device_delivery` is recorded only when the device path ran. Device evidence is the T4 job only. Delivery-species eligibility is preflighted for the whole field before any device mutation, so a post-preflight CUDA failure throws instead of half-applying the step. |
| **Non-delivery oxygen VBF discretization** | Fixed | #392 | The explicit first-order VBF update was present identically on host and device; the issue was a delivery/non-delivery integration-scheme difference, not a GPU-specific divergence. | **Density-coupled VBF sink saw only rank-local agents** | Fixed | #342 | Spec 12 Change 1 builds a per-voxel occupancy histogram from owned agents. | **Exploding inertial mechanics** | Fixed | #281 | The previous update used `Δx = F·dt/(2m)` as a displacement, so a 0.1 µm overlap could move a cell approximately 1.7 m in one 60 s step. Contact could eject cells from the domain, making every spatial observable and boundary/washout attribution produced before the overdamped fix suspect. Mechanics now uses Stokes mobility with `vbf_viscosity` and caps displacement at `0.1·r`. |
| **Cross-boundary HGT to ghost recipient** | Fixed | #265 | Not an under-count: with no ghost-recipient guard a boundary-straddling pair was attempted twice per step, once on each rank, and only the recipient-owner's genome write survived the ghost clear while both ranks incremented `conjugation_transfers` and appended a lineage HGT edge. Acquisitions now commit only on the recipient's owning rank; ghost donors carry the cross-boundary case, so each pair is attempted exactly once globally with no added communication. `domain.ghost_width` must stay >= pili reach or the recipient's owner never sees the donor — `FixConjugation::init` warns. | **VBF drag made the agent velocity update a permanent no-op** | Fixed | #387 | The audit called `drag_force()` "stored but unused"; it was in fact called from `Simulation::module_physics()`, but `a.v` was written *only* by that `-c·v` term, agents start at `v = 0`, and overdamped mechanics never writes `a.v`, so velocity stayed identically zero and `a.x += a.v·dt` never moved anything. Measured over a 60-step VBF-enabled serial run: `max|a.v| = 0` exactly, `max|a.v|·dt = 0`. The explicit update was also unconditionally unstable had `v` ever been nonzero (`c·dt/m = 6.6e7` at `drag_coeff = 1e-9`, `m = 9.1e-16` kg, `dt = 60` s), which rules out entrainment at `bio_dt` without an implicit or analytic relaxation. Removed rather than wired: the velocity integration, the `a.x += a.v·dt` update, `VBF::drag_force()`, the uncalled `VBF::local_capacity()`, and the now-dead `vbf.drag_coeff` / `vbf.carrying_cap` config keys. Agent translation is advection plus overdamped mechanics displacement. `Agent::v` itself is retained (MPI transfer and checkpoint format) and stays zero. |
| **Python manifest writes were non-atomic** | Fixed | #387 | `save_manifest()` and the batch runner's run-level JSON writer opened the destination in `"w"`, so an interruption left a truncated or empty manifest with the previous good generation already gone — a real data-loss path on long Spot campaigns. Writes now go through the hardened `path_utils.write_text_file()`, which serializes fully, writes a same-directory `mkstemp` temp file, `flush()` + `os.fsync()`, `os.replace()`, then best-effort directory fsync (directory durability is *not* claimed where the directory fsync is unsupported, and the temp file is removed on any failure). Path validation and the zero-`pythonsecurity:S6549` requirement are unchanged. |
| **Dead global retardation config keys** | Removed | #300 | `retardation_basic`, `retardation_neutral`, and `retardation_acidic` had no live consumer — their only reader, `FixBacteriocin::retardation_for_pI`, was itself dead code. Removed rather than wired in `0fdf590`: per-plasmid retardation is authoritative (`plasmid.cpp::retardation_from_pI`), and `retardation`/`diff_coeff`/`burst_size` are configurable per plasmid via `plasmid_overrides.<plasmid>.<field>`. The removed spellings now fail closed as unknown config keys. |
