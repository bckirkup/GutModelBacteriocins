## Root cause

`prepare_assay.py` set `gpu_enabled=true` but omitted `metabolism.uptake_limit=delivery`.
GPU diffusion alone records `/run_provenance/chemistry_placement = device`.
`device_delivery` is written only when the device delivery path actually ran
(Stage C inputs already set delivery). The contract correctly requires
`device_delivery`; the generator did not.

## Fix in this PR

`prepare_assay.py` now sets `metabolism.uptake_limit=delivery`. The package test
asserts it. This is an **input-generation** fix; the CUDA binary is unchanged,
but campaign policy still requires a new execution SHA after merge, a rebuild
from that HEAD (so `/run_provenance/git_sha` matches), regenerate+upload of the
12 inputs, and a full assay resubmit before `C_transport_gate` may be recorded.

Do **not** treat this blocked run as a transport pass for Stage D authorization.
